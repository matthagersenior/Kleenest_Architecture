# Mass implementation batch — 2026-08-24

## User-observed failures reconciled

The deployed screenshots exposed three product failures plus a structural deployment/runtime problem:

1. Map showed ingested locations instead of consistently propagating fresh user-location discovery.
2. Route build failed at `live_network_events` RLS publication.
3. Play was reachable but its progression service contract was incomplete.
4. The deployed UI did not reflect the canonical runtime tree reliably. The repository had a duplicate root `src/CanonicalAppRuntime.jsx` whose imports referenced components that actually live under `src/runtime/`. The root entry is now a one-line delegate to `src/runtime/CanonicalAppRuntime.jsx`, eliminating that duplicate router boundary.

## Deployment root-cause finding

The canonical application entry imported `src/CanonicalAppRuntime.jsx`, but that root file contained an obsolete router importing pages from the wrong directory. The actual implemented runtime is under `src/runtime/`. This created a second router boundary and was capable of leaving Pages on stale or inconsistent UI behavior even while runtime files were being improved.

The root file now delegates directly to the runtime router. This is an architectural correction, not a cosmetic workaround.
